# LarpedIn website

A static, framework-free landing page for the extension: hero with download, an animated
Read → Solve → Play demo, the five games, install steps, usage, FAQ.

```
site/
  index.html            the page
  assets/styles.css     all styles; the 5 game colours are defined once in :root (--zip, --queens, …)
  assets/main.js        version label, browser hint, copy button, hero board, demo animation
  assets/og.png         1200×630 social image (generated)
  assets/icon.svg       logo / favicon (+ icon-32.png, icon-180.png, generated)
  downloads/            generated by `npm run site:build` (gitignored)
    larpedin.zip     the unpacked extension, inside a larpedin/ folder
    larpedin.user.js the Tampermonkey userscript
    latest.json           { version, size, sha256, … } read by the page for "v1.0.0 · 19 KB"
  dev/                  dev-only tools (safe to leave out of a deploy)
    serve.mjs             tiny static server
    screenshots.mjs       headless Chromium screenshots + checks
    render-og.mjs, og.html  regenerate og.png and the PNG icons
  screenshots/          output of site:shots (not part of the site)
```

## Build and preview

From the repo root:

```bash
npm install
npm run site:build    # npm run build, then zip dist/extension → site/downloads/ + latest.json
npm run site:serve    # http://localhost:4173/
npm run site:shots    # optional: screenshots + checks (download returns the zip, no console errors, no horizontal scroll)
npm run site:og       # optional: re-render assets/og.png and the PNG icons after design changes
```

`site:shots` and `site:og` use `playwright-core` with Playwright's cached Chromium
(`~/Library/Caches/ms-playwright/chromium-*`), or set `CHROMIUM_PATH`.

Always run `npm run site:build` before deploying: `downloads/` is not committed, and without it
the Download button 404s (the page still renders and falls back to "Free, open source").

## Before going live: replace the placeholders

```bash
grep -rn REPLACE_ME site/index.html
```

- `https://github.com/REPLACE_ME/larpedin`: the public repo (source, issues links).
- `https://REPLACE_ME.github.io/larpedin/`: the deployed URL, used by `canonical`, `og:url`,
  `og:image`, `twitter:image` and the JSON-LD. Social previews need the absolute `og:image` URL to be right.

## Deploy

The deployable folder is `site/` itself (all paths are relative, so it works at a domain root or a subpath).
`dev/`, `screenshots/` and `README.md` are harmless if uploaded, but you can drop them.

- **Netlify / Vercel drag-and-drop:** run `npm run site:build`, then drag the `site/` folder onto
  app.netlify.com/drop (or `npx vercel site/`).
- **GitHub Pages:** Pages serves committed files, so either commit `site/downloads/` on the publishing
  branch (remove `downloads/` from `site/.gitignore`), or use a Pages workflow that runs
  `npm ci && npm run site:build` and uploads `site/` with `actions/upload-pages-artifact`.
- **Any static host / S3 / Cloudflare Pages:** build command `npm run site:build`, output directory `site`.

Make sure the host serves `.zip` as `application/zip` (all of the above do). The download links also
carry the `download` attribute, so browsers save the file instead of navigating.

## Notes

- Colours: the game palette lives in the `:root` block at the top of `assets/styles.css`
  (`--x`, `--x-ink` for AA text, `--x-soft` for tints). Align it with `src/page/theme.ts` there.
- The privacy FAQ was written against the current code: one content script on `www.linkedin.com/*`,
  idle unless the path is a game page, no extension permissions, no background worker, no
  `fetch`/XHR/WebSocket/beacon calls, data kept in the page's `localStorage`. Re-check it if the
  manifest or `src/page/` changes.
- The demo solver in `assets/main.js` is a small plain backtracking search for the 5×5 demo board,
  not the extension's solver; the page says so.
